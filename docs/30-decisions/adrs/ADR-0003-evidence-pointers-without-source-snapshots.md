# ADR-0003：证据指针与摘要，不保存源码快照

> 状态：已接受（Codex 深读策略措辞部分已由已接受的 [ADR-0010](ADR-0010-host-agent-neutral-session.md) 替代）
> 日期：2026-07-24  
> 权威范围：证据持久化、Codex 深读策略和结论可追溯性  
> 上游：[产品目标](../../00-product/vision-and-goals.md)  
> 下游：[证据模型](../../20-architecture/evidence-model.md)、[扫描设计](../../20-architecture/scanning-and-analysis.md)

## 背景

GoodJob 必须解释每个技术、业务与学习结论来自哪里，但复制大量源码到数据库会形成重复、陈旧和敏感的第二份代码库。

## 决策

1. 数据库保存规范化路径、工作树、分支/HEAD、行范围或符号定位、内容哈希、状态、来源类型和短摘要。
2. 数据库不保存完整源码、完整函数体或大段文档快照。
3. 扫描器索引全量模块；准备岗位材料时，Codex 先读取岗位相关证据包，再按问题打开本地原文件。
4. 每个关键 Claim 必须至少关联一个 Evidence；强结论应优先由相互独立的代码、测试、配置或用户背景证据交叉支持。
5. 路径或哈希失效时标记证据过期，要求 refresh，不静默沿用摘要。

## 影响

- 数据库更小，不会成为源码泄露副本。
- 原文件仍是实现事实源，结论可在生成时重新核验。
- 历史文件被删除后只能保留“曾存在”的元数据，不承诺离线重放源码。

## 否决方案

- 保存相关代码片段：历史独立性更好，但重复敏感源码并制造过期内容。
- 只保存最终结论：失去核验、增量更新与面试深挖能力。
- 每次让 Codex 通读全部源码：大型工作区上下文失焦且成本不可控。

## 验证

- 任一关键结论可定位到项目、模块、文件、状态和内容哈希。
- SQLite 内容审计不包含完整源码正文。
- 修改原文件后，旧证据被识别为过期，并在 refresh 后重建。

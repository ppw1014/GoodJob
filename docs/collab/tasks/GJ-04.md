## 背景（为什么做）

契约指针：`DASH-INV-11`、`D-044`、[验收基线 §5](../../40-delivery/acceptance-baseline.md) 的「看板行为」与「门禁的反向用例」两条、[ADR-0008](../../30-decisions/adrs/ADR-0008-single-file-dashboard-and-structured-token-embedding.md) 决策 8 与验证节、[看板呈现契约 §9](../../20-architecture/dashboard-design.md) 规则 8。

`frontend/src/dashboard.ts` 1446 行全是 DOM 渲染，没有任何自动化测试——`scripts/test.mjs` 只覆盖 `model.ts` 的纯函数。作为补偿，`scripts/static-gate.mjs` 用正则去源码里匹配中文 UI 文案：

```js
["coverage limitation scope link", /element\("a", "scope-link", "查看受影响范围"\)/],
```

这是把行为断言写成了文本断言：改一个字就红，行为坏了却可能全绿。结果是 `IMP-28` 目前没有可复现证据。

现成参照：`prototypes/dashboard/verify.mjs` 已经在 WebKit 26.5 + Chromium 151 上跑通过等价核对。**它是设计原型的证据，不是产物的证据**（[验收基线 §5](../../40-delivery/acceptance-baseline.md) 明确禁止拿原型脚本充当运行时证据），本卡要把这套核对移植到运行时前端并改用真实产物作输入。

## 目标（做成什么样）

一条可复现命令，对 Python 侧真实渲染出的看板产物，在 Chromium 与 WebKit 上各跑一遍机检核对并以退出码报告结果，使 `IMP-28` 有可引用的证据；同时 static-gate 不再用源码文本冒充行为断言。

## 接口契约

Architect 给定，不得擅改：

1. 核对脚本位置 `runtime/frontend/scripts/verify.mjs`，入口命令 `npm run verify`。
2. **输入必须是 Python 侧真实渲染的产物**，不是原型 fixture、不是手写 HTML。生成方式：调用 runtime 的 `render_dashboard_html` 产出一份 HTML 到被忽略的临时目录，脚本读取该文件。产物生成步骤写进 `npm run verify` 或其前置脚本，Owner 一条命令可复现。
3. 断言集合至少包含两组。**第一组：产物级健康性**
   - 两引擎**干净加载**阶段控制台错误为零、页面错误为零；
   - 零外部请求（非 `file:` 协议的请求一律计入失败）；
   - 多宽度 × 全视图零横向溢出（宽度至少含 1440 / 1280 / 1024 / 768 / 375，视图覆盖全部路由）；
   - 打印分支生效（导航与交互控件隐藏、折叠展开、locator 完整）；
   - `forced-colors: active` 下五组状态仍可靠图标与文字区分。

   **第二组：契约 7 所删源码检查的行为等价物**（一一对应，不得少）
   - RoleLens 假设**渲染进 DOM 并可见**（替代 `role_lens.assumptions` 源码匹配）；
   - 覆盖限制的「查看受影响范围」是一个**可聚焦、可激活的链接**，激活后确实跳到受影响范围（替代 `element("a", "scope-link", …)` 源码匹配）；
   - 该链接**不位于侧栏导航网格内**——按 DOM 祖先关系判定，不是按 class 名字符串（替代那条 `nav-link` 反向检查）；
   - 搜索框的延迟聚焦行为生效：触发搜索后焦点最终落在预期元素（替代 `pendingSearchFocus` 源码匹配）；
   - 聚焦态项目可被激活并导致视图切换（替代 `link.click()` 源码匹配）。
4. **阳性对照必须存在**：脚本主动注入一次 `style` 属性，该操作**必须**触发 CSP 违规。对照不成立即判定 CSP 未生效，脚本以失败退出并明确说明其余断言作废。
5. **断言切点**：干净加载阶段的错误快照必须在任何探针动作之前取得；探针（阳性对照、外部请求探测）引发的错误单独计数，不混入干净加载错误。工具自身注入的样式（Playwright 的 `fullPage` 截图会注入 `<style>`）同样会被这份 CSP 拒绝，属于预期，不得因此放宽策略。
6. 失败时退出码非零，并打印足以定位的结构化结果（哪个引擎、哪个宽度、哪个视图、哪条断言）。
7. `static-gate.mjs`：
   - **删除**全部以「源码中必须出现某段字符串或某句 UI 文案」为形式的检查项：当前 `dashboard.ts` 的四条 required-pattern（`role_lens.assumptions`、`pendingSearchFocus`、`link.click()`、`element("a", "scope-link", "查看受影响范围")`）与其后那条 `nav-link` 反向检查，共 5 条；
   - **删除是有条件的**：每删一条，契约 3 第二组里对应的行为断言必须已经存在并通过。**先补后删**，不得先删后补，更不得只删不补。若某条行为断言在浏览器里做不出来，停工 L1 说明是哪条，不要自行判断"这条不重要"；
   - **保留并加强**禁用 API 与禁止资源引用的静态检查：现有 `.style(\.|\[)` 规则保留，并确认它覆盖 `element.style` 的任何属性赋值（`D-044`）；
   - CSS 侧的结构性检查（`@import`、`url(`、`overflow-x`、必需的 `@media` 分支）保留。
8. `npm test` 与 `npm run verify` 的关系由实现侧选定其一并在交付报告说明：合入 `npm test`，或作为发布前必跑的独立命令。选定后 `README.md` 的门禁命令段同步更新。这是绿区自选项，理由写交付报告。

## 实现指引

- 参照 `prototypes/dashboard/verify.mjs` 的结构，尤其是它对断言切点的处理（`cleanLoadErrors` 在探针之前快照）——那是踩过坑之后的写法。
- 视口截图比 `fullPage` 更可靠：`position: sticky` 在 `fullPage` 捕获中会渲染成未吸附状态，容易误导判读。
- Playwright 浏览器二进制不进仓库；`npx playwright install webkit chromium` 作为一次性准备步骤写进 README。
- 产物临时目录必须进 `.gitignore`。

## 验收标准（DoD）

- [ ] 门禁全绿：前端 `npm ci && npm test`；Python 侧 `uv run pytest -q` 不受影响
- [ ] `npm run verify` 在 Chromium 与 WebKit 上各跑一遍，全部断言通过并以退出码 0 结束
- [ ] **自检用例**：临时改坏一处渲染行为（例如去掉一个状态图标或让某视图溢出），`npm run verify` 必须变红；恢复后变绿。交付报告写明改了哪一处、脚本报了哪条断言——这是证明它断言的是行为而不是文本的唯一证据
- [ ] 阳性对照生效：人为让 CSP meta 失效（本地临时试验，不提交）时脚本报告"对照不成立"并失败
- [ ] `static-gate.mjs` 中不再存在任何 UI 文案匹配；`npm run lint` 仍通过
- [ ] **删除的 5 条源码检查与新增的 5 条行为断言一一对应**：交付报告给出对照表（删了哪条 → 由哪条行为断言接管），无一遗漏
- [ ] 对照表中每条行为断言各做一次**反向验证**：改坏它保护的那个行为，该断言必须单独变红（可与自检用例合并做，但要逐条给出结果）
- [ ] 新增依赖只有 `playwright`，版本精确锁定；交付报告列出实际新增依赖全表
- [ ] `README.md` 门禁命令段与实际命令一致

- **不修改 `dashboard.ts` / `dashboard.css` 的渲染行为**。若核对脚本发现真实呈现缺陷，按 L2 上报，由 Architect 决定另开卡——本卡只建门禁，不修被门禁发现的问题。
- 不改 `prototypes/` 下任何文件。
- 不把原型脚本直接软链或复制后当运行时证据。
- 不新增除 `playwright` 外的任何依赖；不引入测试框架。
- 不放宽 CSP 或任何静态禁用规则来让脚本通过。
- 卡面与实际代码矛盾时停工 L1。

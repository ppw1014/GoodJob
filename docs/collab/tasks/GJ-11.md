## 背景（为什么做）

契约指针：[验收基线 §1](../../40-delivery/acceptance-baseline.md)、[protocol §7 体量披露制](../protocol.md)。

来源是 [GJ-07](GJ-07.md) 交付报告（信道 #19）的 L3 建议，Architect 验收时采纳并扩了半张（见信道 #20）。

`scripts/check-doc-links.py` 是 357 行手写 markdown 行内链接解析器，**在门禁路径上，且零测试**。它在开发期间被双轴 review 抓出 6 个缺陷——这说明它是个容易写错的东西，不是说明它现在写对了。

关键在于失败方向不对称：

- 解析**过严**（把非链接当链接）→ 门禁**误红**。吵，但看得见，会被立刻修。
- 解析**过松**（把真链接漏掉）→ 门禁**误绿**。**断链存在但门禁说没有。**

第二种正是 GJ-07 立卡要消灭的东西。现在这张卡的产物自己就有这个风险，且没有任何测试拦着。

Architect 验收实测的分支分布：

| 部分 | 行数 | 说明 |
| --- | --- | --- |
| 契约 8 + 9 明文要求的核心 | 176 | 围栏、行内代码、转义、目标解析、git 枚举 |
| 容器内围栏与完整链接闭合解析 | 118 | **本仓库当前零实例**：blockquote 内围栏 0、list 行首围栏 0、`<>` 目标 0、带 title 链接 0 |
| `O_NOFOLLOW` / descriptor walk | 40 | 由 protocol §8「路径代码」条款推导，该条本意指运行时 |

## 目标（做成什么样）

这个检查器的每一条行为分支，要么有一个会在它坏掉时变红的测试，要么不存在。门禁自己被门禁守着。

## 涉及范围

- **允许**：`scripts/check-doc-links.py`、新增 `scripts/test_check_doc_links.py`（文件名可自选，理由写交付报告）、`Makefile`（把测试接进门禁）、`README.md` 门禁命令段（如目标有变）
- **禁止**：其余一切文件。特别是 `runtime/` 下的任何文件、`docs/` 下的契约文档、`docs/collab/protocol.md`
- **零新增依赖**：测试用标准库 `unittest`，不引入 `pytest` 或任何第三方库到仓库根

## 接口契约

Architect 给定，不得擅改：

1. 测试用 Python 3 标准库 `unittest`，不依赖 `runtime/` 的 uv 环境——根脚本的测试不该耦合到 Skill 包。**调用方式固定为显式命名测试模块**：`python3 -m unittest scripts/test_check_doc_links.py`（信道 #25 L1 → #26 裁决修订；原条款写「裸 `python3 -m unittest`」，是过度指定且留有假绿路径）。

   **不得**改用 discovery 形式（裸 `python3 -m unittest` 或 `discover -s scripts`），也**不得**为让 discovery 生效而新增 `scripts/__init__.py`。理由是实测出来的——测试文件被改名后：

   ```text
   裸 python3 -m unittest          -> Ran 0 tests / OK / 退出 0   假绿
   discover -s scripts             -> Ran 0 tests / OK / 退出 0   假绿
   显式命名测试模块                 -> 非零硬错                    被接住
   ```

   `unittest` 在"一个测试都没跑"时报 `OK` 并退出 0。门禁用 discovery 形式，等于给自己留一条"测试没了但门禁还绿"的路——正是本卡要消灭的失败类。
2. 测试接进 `make gate-docs`：**先跑测试，再跑检查**。测试失败即门禁红。理由是本卡的全部意义——检查器自己必须被守住，而不是只在有人想起来时被验证。
3. **覆盖依据是「失败方向」，不是「行数」**。必须优先覆盖所有**误绿**路径，即"某个真实断链因为解析细节而没被报出来"。至少包含：
   - 围栏内 / 围栏外的同一链接文本，一绿一红（契约 9 的双向）；
   - 行内代码内 / 外的同一链接文本，一绿一红；
   - 转义的 `\[` 不构成链接；
   - 目标带 `#` 锚点、`?query`、`%` 编码时的解析结果；
   - `http` / `https` / `mailto` / 纯锚点被跳过；
   - git 枚举：被 ignore 的目录下的 md **不进**扫描集合，未跟踪但未被 ignore 的新 md **进**扫描集合。
4. **每条测试必须配一次变异自检**：改坏它保护的那条分支，该测试必须**单独变红**。交付报告逐条给出「改了哪一行 → 哪个测试红了」。只有测试没有变异证据的，等于没覆盖——这是本项目一贯口径（[验收基线 §1](../../40-delivery/acceptance-baseline.md)）。
5. **写完测试后做一次收敛**：凡是没有任何测试覆盖到的行为分支，二选一——补测试，或**删掉**。交付报告给出每个分支的去向表（分支 → 补测试 / 删除 / 理由）。
   - 上表中「本仓库零实例」的 118 行是这一条的主要对象。**不预设结论**：你可以为它们写测试并保留，也可以删除。但不允许"既没测试也不删"。
   - 判断依据说清楚：它们防的是**误红**（可见），核心 176 行防的是**误绿**（静默）。两者优先级不同，你的取舍要落在这个差别上。
6. **不改检查器的对外行为**：命令行接口、输出格式（`文件:目标`）、退出码语义不变。收敛只能删除无覆盖分支，不得改变有覆盖分支的判定结果。
7. `O_NOFOLLOW` / descriptor walk 那 40 行**保留，不动**。它的取舍牵扯 protocol §8「路径代码」条款的适用范围（该条本意指运行时，字面覆盖到了 dev 脚本），属协议措辞问题，不在本卡——见信道 #20 §5，等 Owner 裁决。

## 实现指引

- 测试造 fixture 用 `tempfile.TemporaryDirectory` + 真实文件，不要 monkeypatch 文件系统——这个脚本的行为有一半在文件系统语义上，打桩会把要测的东西测没。
- 契约 3 最后一条（git 枚举）需要在临时目录里 `git init` 并写 `.gitignore`。可以接受，`git` 已是本项目既有前提。
- 契约 5 的收敛顺序是**先测后删**，不要反过来。删掉再发现该分支其实被某份文档依赖，会变成误红事故。
- `make gate-docs` 里测试与检查两步写成**独立配方行**，保留失败定位（与 GJ-07 前端族同一写法）。

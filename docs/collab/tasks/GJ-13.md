## 背景（为什么做）

[验收基线 §3](../../40-delivery/acceptance-baseline.md) 定义 `IMP-*` 场景，[看板呈现契约 §12](../../20-architecture/dashboard-design.md) 定义 `DASH-*` 场景，[验收基线 §6](../../40-delivery/acceptance-baseline.md) 要求它们全部有可复现实证。交接盘点只确认少量卡面引用与部分看板断言，现有测试名称本身不能证明完整场景，也不能区分“已有但未挂接”与“确实缺证据”。

本卡先固定证据事实，不修产品、不补测试。后续任务只能引用账本中的缺口，不再手抄一份列表。

## 目标（做成什么样）

新增一份按代码基线冻结的发布验收证据账本，使 Architect 能对每个 `IMP-*` 与 `DASH-*` 判断：已经完整证明、只证明一部分、没有证据，或被 Owner/外部条件阻塞；每个判断都能从一条精确命令复现，并清楚指出尚未覆盖的契约子句。

## 接口契约

`acceptance-evidence.md` 是**证据记录，不是产品契约**，必须包含：

1. 顶部元数据：证据基线 commit、记录生成日期、证据分类规则、状态词典；基线由领卡后实际 `git rev-parse HEAD` 得出，不在卡面写死。
2. `IMP` 主表：ID 集合以验收基线 §3.2 的实际标题为唯一事实源；每个 ID 恰好一条。
3. `DASH` 主表：ID 集合以看板呈现契约 §12 的实际标题为唯一事实源；每个 ID 恰好一条。
4. 每条至少包含：`status`、`evidence_class`、精确复现命令/测试节点或跨引擎 assertion 名、已覆盖子句、未覆盖子句/阻塞条件。
5. `status` 仅允许：
   - `verified`：该 ID 的“必须验证的场景”和“通过条件”全部由适格证据覆盖；
   - `partial`：至少一个契约子句有适格证据，但不完整；
   - `missing`：没有适格证据；
   - `owner_blocked`：仓库内可完成的证据已经齐全，只差 Owner 决策、真实工作区授权或人工视觉判断，且仓库内证据无法替代；只要仍有仓库内缺口就必须记 `partial`，不得用阻塞状态遮住它。
6. `evidence_class` 仅允许 `automated`、`synthetic_e2e`、`real_workspace`、`owner_visual`，可多值；不得用较低层证据冒充较高层证据。
7. 文末给出按状态计算的汇总与下一批候选；汇总数字必须由表内条目现场计算，不把交接时的观测值当常量。

## 审计规则

- 代码存在、测试名、注释、历史任务卡声称“覆盖”都只能作为线索；必须打开测试/门禁实现，逐条对照场景与通过条件后才能定 `verified`。
- 自动化证据必须给出可直接运行的命令。pytest 参数化函数可引用函数级 node ID；前端行为证据必须同时写 `npm run verify` 与实际 assertion 名。
- 命令成功集合必须非空。不得用“零测试退出 0”“两侧失败集合都为空”“夹具偶然命中”作为证据。
- 真实工作区、Owner 视觉判断、安装副本调用尚未执行时如实标为 `missing` 或 `owner_blocked`，不能由单测替代。
- 同一个证据可以支持多个 ID，但每个 ID 都要解释它具体区分了哪个正确/错误行为；只列路径不算映射。
- 若发现权威文档互相矛盾，停工按 L1 上报；若只是现有测试缺场景，继续完成账本并按 L2 汇总，不在本卡补测试。

## 验收标准（DoD）

- [ ] 从两个上游权威表动态提取 ID 集合，与账本双向比对：无缺失、无额外、无重复；不在卡面持有第二份 ID 清单。
- [ ] 每个 `verified` 条目都逐子句对照，并至少给出一个非空、可复现、能区分正确/错误行为的证据入口；不能证明完整时降为 `partial`。
- [ ] 每个 `partial`/`missing`/`owner_blocked` 都写出最小缺口和建议归属，足以让 Architect 后续一卡只解决一个目标。
- [ ] 逐条实际运行所有被引用的 Python 测试节点；前端 assertion 统一以完整 `npm run verify` 复现，不靠源码字符串匹配替代行为断言。
- [ ] `make gate-release` 在本卡分支全绿，且报告中给出运行 HEAD；若环境缺失导致不能运行，按 L1 停工，不把“以前绿过”记为本卡证据。
- [ ] `git diff --stat` 只包含允许文件与信道追加；运行时、测试、权威契约、个人状态零改动。
- [ ] 交付报告按状态给出动态汇总、下一批建议与全部 L2/L3；不在信道复制账本全文。

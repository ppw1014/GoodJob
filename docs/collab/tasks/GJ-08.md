### 一、数据区转义目前没有运行期守卫

GJ-01 把结构门禁的判定范围收窄到产物结构后，数据区不再被任何**运行期**规则检查。验收时我做了变异测试：撤掉「范围收窄」但保留 `=` 转义，`test_reporting.py` 22 个用例**全绿**。穷举探测确认了原因——`=` 与 `<` 都被转义后，结构正则在数据区永远不可能命中，两层是纯冗余，第二层无法被任何输入驱动的测试区分。

这不是坏事，但意味着**转义本身的正确性只由测试夹具保证，没有运行期不变量**。若 `_embedded_json` 的某个 `replace` 将来被删掉，产物会带着可断开 `</script>` 的裸字节发布，只有恰好覆盖到的测试会红。

正确形态是两个**各自可测**的层：结构门禁只判产物结构；数据区由自己的规则判「必须已完全转义」。

### 二、归因散文投影在接缝处漏检

`_personal_attribution_prose` 剔除非散文 token 后**无分隔符**直接拼接，被剔除处不留词边界：

```text
['结果', code'X', 'I led this']  ->  '结果I led this'  ->  \bI\b 不命中
```

这**不是批次 A 引入的回归**（改动前的全串拼接在同样输入下同样不命中），但插入分隔符会严格更保守。

## 接口契约

Architect 给定，不得擅改：

1. `render_dashboard_html` 在拼装产物前，对 `_embedded_json` 的输出增加**渲染期后置断言**：数据区不得含裸 `<`、`>`、`=`、`&`、U+2028、U+2029 及现有可见控制符集合。违反抛 `InvalidInputError`，`code` 不变。
2. 该断言是**独立于结构门禁的一层**：结构门禁只看产物结构，数据断言只看数据区。**不得把两者合并回一次全文匹配**——那正是 `D-043` 禁止的形态。
3. 断言的字符集合与 `_embedded_json` 的转义集合必须来自**同一处定义**，不得各写一份常量。转义集合将来增删时，断言自动跟随。
4. 归因判定改为**双投影并集**（信道 #9 L1 → #10 裁决修订，原「插入换行符分隔」条款作废）：
   - 投影甲＝参与 token 值**无分隔拼接**（即当前实现，保持不变）；
   - 投影乙＝同一批 token 值以**换行符分隔**拼接；
   - 判定时**沿用 `_PERSONAL_PATTERNS` → `_OMITTED_SUBJECT_PERSONAL_PATTERNS` 的既有优先级顺序逐个 pattern 检查，任一投影命中即判定为该归因并返回**。不得先各自判定再合并结果——那会改变优先级语义。
5. 两个投影**只作用于归因判定**；`_resolve_tokens` 返回的完整 statement 拼接保持无分隔符，契约不变。
6. **单调性是本条的硬约束**：改动后的判定必须是改动前的**严格超集**——任何在当前实现下能检出某归因的输入，改动后必须检出**同一个**归因，不得降级为更弱的归因（尤其不得降级为 `personal_assertion`）、也不得变为不检出。这正是 #9 L1 拦下的问题：中文 `_PERSONAL_PATTERNS` 依赖 `我实现` 式字面相邻，任何分隔符都会击穿它，而 `_attribution_covers` 中 `responsible` 覆盖 `personal_assertion` 却不覆盖 `implemented`，降级会让「声明 responsible + 陈述我实现了」从被拒变成通过。
7. 契约 4 只会让检出更宽（例如「单位矩阵 I」这类非第一人称的 `I` 更容易被判为个人归因）。**这是刻意选择的方向**：检出偏严只会要求补个人上下文，漏检则会让个人归因绕过校验。不得为压制这类误报去收窄 `_FIRST_PERSON_PATTERN`，也不得修改 `_PERSONAL_PATTERNS` 或 `_attribution_covers` 的任何取值。

## 实现指引

- 契约 3 的做法之一：把转义映射抽成模块级常量（字符 → 转义序列），`_embedded_json` 用它做替换，断言用它的键做检查。注意 `&` 必须先替换的既有顺序不能破坏。
- 契约 1 的断言是 O(n) 单次扫描，发生在冻结之后、拼装之前；不要放进 `_validate_dashboard_document`（那是结构层）。
- 契约 4 的投影乙用换行符而不是空格：换行符不会出现在正常 token 值里参与构词。
- 契约 4 的形态大致是：`for attribution, pattern in _PERSONAL_PATTERNS: if pattern.search(甲) or pattern.search(乙): return attribution`，两组 pattern 表依次走完。这个写法天然满足契约 6 的单调性——投影甲原样保留在判定里，原有命中不可能丢。
- 为什么不能改成「给中文 pattern 加 `\s*` 容忍分隔符」：那会修改 `_PERSONAL_PATTERNS` 的取值，属契约 7 禁区，且影响面覆盖所有位置而不只是 token 接缝。

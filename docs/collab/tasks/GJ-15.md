## 接口契约

### 契约 1：公共数据与产物契约不变

1. `ReportBundle` 仍为 `report-bundle-v1`，Markdown、HTML、manifest、数据库与 CLI 的字段/语义均不变；不得为测试新增持久化字段或测试专用 bundle 字段。
2. HTML 仍是可单独复制和 `file:` 打开的单文件产物，不新增网络请求、外部资源或常驻服务。
3. `render_report_markdown` 与 `render_dashboard_html` 必须接收**同一个已计算 digest 的冻结 bundle**；验证脚本不得分别改写两份输入后再声称同源。

### 契约 2：最小 DOM 语义钩子

为避免把 UI 文案或 class 名当数据解析，允许且仅允许在既有元素上增加以下不可见 `data-*` 属性；属性必须通过 DOM `dataset` / `setAttribute` 安全赋值，不拼接 `innerHTML`：

- `.forensic-strip`：`data-package-status`、`data-preparation-run-id`、`data-bundle-sha256`；值与 bundle 原值逐字相等，显示文本继续遵循现有设计。
- `.claim-item`：`data-claim-id`、`data-facets`；`data-facets` 是按输入顺序的 JSON 字符串数组，不使用逗号拼接。
- 每个实际呈现的 Evidence relation 根元素：`data-evidence-id`、`data-relation`、`data-validity`、`data-commit-state`、`data-supported-facets`；facets 同样是 JSON 字符串数组。
- `.degradation-item`：`data-limitation-id`、`data-kind`、`data-severity`、`data-project-id`；`project_id = null` 时使用空字符串，不造哨兵 ID。
- `.route-error`：`data-error-kind="contract-version-mismatch"` 仅用于不支持的版本；普通未知同版本深链使用既有错误呈现且不得冒充该 kind。

这些钩子是冻结内容的可机读镜像，不是新的公共 schema，也不得隐藏或替代用户可见的文字/图标通道。若现有渲染结构无法在不改公共契约的前提下满足该列表，停工 L1。

### 契约 3：DASH-10 双快照与跨版本深链

1. 合成夹具从同一个基础 bundle 生成两份**独立 HTML 文件**并在同一浏览器 context 的两个 page 中同时打开：
   - 两份的 `role.name`、`role_lens.role_lens_id`、JD 输入与岗位假设完全相同；
   - 一份 `package_status=completed`，另一份 `package_status=partial`；
   - `preparation_run_id` 与重新计算后的 `bundle_sha256` 各不相同。
2. 两页身份条必须分别精确映射各自的 status/run/hash；断言既要证明同岗位，也要证明两份身份不相等，不能只检查“身份条存在”或“文案里有 completed/partial”。
3. 在其中一页粘贴不支持的 `#/v9/overview` 深链后必须同时满足：
   - `main .route-error[data-error-kind="contract-version-mismatch"]` 可见；
   - 可见错误正文明确包含“该链接属于其他契约版本”；
   - `location.hash` 仍保留该跨版本路径，不静默改写为 `v1`；
   - `main` 内没有 `.view`、`.view-title`、`.claim-item` 或来自另一快照的对象内容。
4. 对 `v0`、`v2`、`v9` 以及 URL 编码的非版本 payload 至少各跑一次同类失败关闭断言；不得通过源码 `rg`、常量存在或仅检查溢出来代替浏览器行为。

### 契约 4：DASH-12 同源语义投影

验证脚本必须从同一冻结 bundle 真实生成 `report.zh-CN.md` 与 HTML，再从**Markdown 文本**和**浏览器实际 DOM**分别独立提取规范化投影。禁止从 HTML 的 `#report-data` 读取 bundle JSON后与原 bundle 自比，禁止只比较文件 hash，禁止只检查某段字符串存在。

规范化投影至少包含：

- 每个 Claim：`claim_id` 与有序 `facets`；
- 每条 Claim→Evidence relation：`evidence_id`、`relation`、有序 `supported_facets`，以及所指 Evidence 的 `validity`、`commit_state`；
- 每条限制：两种产物都能观察到的作用域（全局或所属 Project ID）、`kind`、`severity`，以及 message / impact / remediation 的可见 token 文本。Markdown 当前不输出 `limitation_id` 或 `filter_route`，因此它们不是跨产物相等性的锚点；HTML 的 `data-limitation-id` 仍必须非空、唯一，用于发现 DOM 漏项/重复，但不得拿它单独判定 parity。

比较前可按“作用域 + kind + severity + 三段可见文本”的稳定语义键排序，但字段值和列表内容必须逐项精确相等。项目限制的作用域必须从 Markdown 的 Project ID 结构上下文与 HTML 的项目视图上下文分别提取；全局限制不得借 HTML 的隐藏字段补造 Markdown 没有的项目 ID。HTML 不得缺项、增项或替换成 Markdown 没有的结论。夹具必须非空，并同时覆盖：至少 4 个 Claim、`current/stale/missing/plan` 四种 Evidence validity、至少 5 种 commit_state、多个 Claim facets、多个 supported facets，以及至少一条全局限制和一条项目限制；零条目投影不得判绿。

Markdown parser 只解析 renderer 已有的结构化 Claim/Evidence/限制行，并在缺字段、重复 ID、无法解析或数量不符时失败关闭；不得“解析失败就跳过”。DOM 投影只读取用户实际可见的渲染元素及契约 2 的钩子。

### 契约 5：验证输出与 assertion 名

`npm run verify` 的 JSON 结果继续使用 `goodjob-browser-verification-v1`，并在 Chromium、WebKit 各产生以下非空 assertion（可增加细分项，不得改名或只在单引擎运行）：

- `dash10-completed-snapshot-identity`
- `dash10-partial-snapshot-identity`
- `dash10-same-role-distinct-snapshots`
- `dash10-cross-version-deep-link-rejected`
- `dash10-cross-version-no-wrong-object`
- `dash12-claim-evidence-parity`
- `dash12-limitation-parity`
- `dash12-no-html-only-conclusions`

正常运行中任一 assertion 缺席、重复名遮蔽、投影为空或 `ok=false` 都必须使命令非零退出。原有 assertion 继续运行，不得删减或降低。

## 实现指引

- 复用现有 `verify.mjs` 的 synthetic bundle、Python 子进程 renderer、`file:` URL、`record()` 和双引擎循环；不要引入第二套测试 runner。
- 建议将“生成同源 Markdown/HTML”“提取 Markdown 投影”“提取 DOM 投影”“比较投影”拆成小函数，错误详情输出首个不一致的稳定 ID/字段，避免只报 `false`。
- 双快照文件写到已忽略的 `frontend/verify-out/`；验证结束不要求提交，也不得把临时产物纳入 Git。
- `dashboard.ts` 只增加契约 2 的语义钩子与跨版本错误 kind；现有导航、视觉布局、文案、键盘行为和 CSP 不作顺手重构。
- 恶意 ID、facet 或 limitation 文本继续走 DOM API 与 `appendTokens`；不得把 JSON facets 直接拼进 HTML 字符串。
- 绿区自主决策仅限测试辅助函数命名、临时文件名和 projection 内部数据结构；必须在交付报告“自主决策”节披露。任何允许列表外文件、公共字段、依赖或 renderer 改动都是 L1。

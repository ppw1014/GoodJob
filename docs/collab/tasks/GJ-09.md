## 背景（为什么做）

契约指针：`D-043`、[看板呈现契约 §9](../../20-architecture/dashboard-design.md) 规则 7、[验收基线 §1](../../40-delivery/acceptance-baseline.md)。

**这是出卡侧（我）的疏漏，不是 GJ-08 的实现缺陷。**GJ-08 的契约 3 要求转义集合与后置断言同源，实现严格照做，DoD 逐条成立。

同源是对的选择——它让"转义集合增删时断言自动跟随"。但它有一个必然代价：**删掉映射里任一条目，会同时失去该字符的转义与对它的断言，两层一起消失，没有任何信号。**这道防线的强度因此完全取决于是否有**独立于该映射**的测试锚住集合内容。

GJ-08 验收时我做了三次额外变异，结果是：

```text
从 _EMBEDDED_JSON_ESCAPES 删掉 "="        -> 5 failed（被硬编码参数表接住）
从 _EMBEDDED_JSON_ESCAPES 删掉 "&"        -> 167 passed，全绿
从 _VISIBLE_CONTROL_LABELS 删掉 U+2028    -> 1 failed
```

`=` 被接住，是因为 `test_embedded_json_validation_rejects_unescaped_data` 的参数表硬编码为 `("<", ">", "=")`——而这三个字符，正是我在 GJ-08 的 DoD 里点名要求直接覆盖的三个。**测试覆盖恰好等于我列举的范围，不多一个。**

`&` 全绿。U+2028 变红，但不是因为有针对它的断言，而是某个既有夹具恰好含有该字符——这正是[验收基线 §1](../../40-delivery/acceptance-baseline.md)所说的"只在固定夹具下成立的门禁不是门禁"。

GJ-08 的契约 1 点名了七类字符（`<`、`>`、`=`、`&`、U+2028、U+2029、可见控制符集合），DoD 却只要求直接覆盖其中三类。本卡补齐这个差额。

## 目标（做成什么样）

`_EMBEDDED_JSON_ESCAPES` 的**键集合本身**被一处独立断言锚住：任何人删改集合内容，必须同时显式改动一处写着期望值的测试，不存在"改一处、两层一起静默消失"的路径。

## 涉及范围

- **允许**：`runtime/tests/test_reporting.py`
- **禁止**：其余一切文件。**特别是 `reporting.py`——本卡不改任何产品代码**
- 零新增依赖

## 接口契约

Architect 给定，不得擅改：

1. 新增一个测试，把期望的转义字符全集**硬编码在测试文件里**（字面量，不从 `reporting` 模块导入、不由 `_VISIBLE_CONTROL_LABELS` 推导），断言它与 `_EMBEDDED_JSON_ESCAPES` 的键集合**互为子集**（两个方向都断言，缺一不可：只断言单向会漏掉"多加了字符"或"少了字符"其中一种）。
2. 该测试的失败信息必须能让人直接看出**多了哪个 / 少了哪个字符**，不能只报 `assert False`。
3. `test_embedded_json_validation_rejects_unescaped_data` 的参数表扩展到覆盖全集的每一类字符（至少：`&`、`<`、`>`、`=`、U+2028、U+2029，以及可见控制符里任取一个）。参数表同样**必须是字面量**，不得写成 `list(_EMBEDDED_JSON_ESCAPES)`——那会退回同源，本卡就白做了。
4. **不修改 `_embedded_json`、`_validate_embedded_json`、`_EMBEDDED_JSON_ESCAPES` 或 `_VISIBLE_CONTROL_LABELS` 的任何内容。**本卡纯补测试锚点。若实施中认为产品代码确有问题，L3 上报，裁决前不得改。

## 实现指引

- 契约 1 的自然写法是 `assert set(EXPECTED) == set(_EMBEDDED_JSON_ESCAPES)`，`pytest` 对 set 比较的差异输出已经满足契约 2；若用别的写法，自行保证可读性。
- 字面量里的 U+2028/U+2029/控制符请用 `" "` 这类转义写法，不要贴裸字符——裸字符在 diff 与终端里不可见，将来改动时看不出改了什么。
- 不需要为"`&` 必须先替换"补测试：当前所有替换的产物都是 `\uXXXX` 形式，不含任何被替换字符，替换顺序不影响结果。既有的 `test_embedded_json_escape_mapping_drives_every_required_escape` 已经断言了每个字符都不以原字符出现，这一点无需重复。

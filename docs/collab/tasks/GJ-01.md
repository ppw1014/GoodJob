## 背景（为什么做）

契约指针：[ADR-0008](../../30-decisions/adrs/ADR-0008-single-file-dashboard-and-structured-token-embedding.md) 决策 5 与决策 8、[看板呈现契约 §9](../../20-architecture/dashboard-design.md) 规则 2 与规则 7、`DASH-INV-11`、`D-043`。这些契约已在评审同一变更中落定，本卡是让实现追上契约。

`_validate_dashboard_document` 在整份 HTML 上匹配 `\sstyle\s*=`，而这份 HTML 包含内联的 `ReportBundle` JSON。嵌入转义只覆盖 `<`、`>`、`&`，`style=` 原样保留，于是工作区里任意一段 `<div style="…">` 被 `code` token 引用后就能让渲染失败。

失败不可恢复：`render()` 捕获后走 `_record_failure_if_running` 与 `_cleanup_failed_attempt`，run 停在 `render_failed`；而 `ReportBundle` 已冻结，重试同一份必然同样失败，Owner 只能重跑整轮分析。首版深读覆盖 TypeScript/TSX，触发面不窄。

复现（当前必然抛错）：

```bash
cd .agents/skills/goodjob-career-review/runtime && uv run python -c "
from goodjob.reporting import render_dashboard_html, report_bundle_sha256
b={'contract_version':'report-bundle-v1','x':[{'kind':'code','value':'<div style=\"color:red\">hi</div>'}]}
b['bundle_sha256']=report_bundle_sha256(b); render_dashboard_html(b)"
```

## 目标（做成什么样）

含 `style=`、`<img …>`、`</script>` 等标记片段的 `ReportInlineToken` 值可以正常进入看板产物：内容以转义序列出现、不产生任何元素、不产生任何可点击目标，**且渲染成功**。产物的结构性安全检查强度不降低。

## 涉及范围

- **允许**：`runtime/src/goodjob/reporting.py`、`runtime/tests/test_reporting.py`
- **禁止**：其余一切文件。特别是不得改动 `docs/`（契约已定稿）、`dashboard.js`/`dashboard.css`/`frontend/`（属 GJ-04）、`analysis.py`（属 GJ-02）
- 零新增依赖（运行时 `dependencies = []` 是红区，见[协议 §8](../protocol.md)）

## 接口契约

Architect 给定，不得擅改：

1. `_embedded_json` 的转义集合在现有 `<`、`>`、`&`、U+2028、U+2029、可见控制符之外**新增 `=`**，输出为对应的 `\uXXXX` 序列（`\u003d`）。转义发生在 canonical JSON 之后，**`bundle_sha256` 仍只计算在 canonical JSON 上，不受影响**。
2. `_validate_dashboard_document` 的**结构性检查只作用于产物结构**，`<script id="report-data" type="application/json">` 与 `</script>` 之间的数据区不参与。判定范围由渲染时已知的拼装边界给出，不引入 HTML 解析器。
3. 上述两条**都要做**。只做转义会让检查范围仍然错误，只做范围收窄会让数据区继续携带形似属性的字节。
4. 现有的 `<(?:img|iframe|object|embed|link)` 检查、`unsafe-inline`/`unsafe-eval` 检查、CSP 哈希一致性检查，判定范围统一按第 2 条处理——它们目前"安全"只是因为 `<` 恰好被转义，属于依赖巧合。
5. 检查失败时抛出的仍是 `InvalidInputError`，`code` 不变。

## 实现指引

- `render_dashboard_html` 自己拼装 HTML，数据区的起止字符串是已知常量，据此切分即可，不需要解析。
- 转义顺序注意：`&` 必须先于其他替换，否则会把新产生的 `\u003d` 里的字符二次替换——现有代码已是这个顺序，新增 `=` 时保持。
- 产物字节会变（多了 `\u003d` 的转义），`test_reporting.py` 中断言产物内容的用例需要相应更新，这属于本卡范围。

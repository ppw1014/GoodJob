## 背景（为什么做）

契约指针：[扫描与分析设计](../../20-architecture/scanning-and-analysis.md)、`SCAN-04`、[协作协议 §红区](../protocol.md)。

`scanner.py` 现在 4189 行，其中 `WorkspaceScanner` **一个类 3317 行、66 个方法**，同时承担遍历、ignore、Git 元数据与子进程沙箱、文件分类、数据库持久化、证据生成、覆盖聚合。按方法名归簇实测：

| 簇 | 方法数 | 行数 |
| --- | --- | --- |
| **Git 元数据 / 历史 / 外部仓库沙箱** | **28** | **1048** |
| 遍历 / ignore / 分类 | 5 | 427 |
| 其余（持久化、证据、覆盖聚合等） | 33 | ~1840 |

关键不在于行数，在于**红区代码埋在里面**：Git 子进程调用、超时与输出上限、外部仓库授权与路径校验、`O_NOFOLLOW` 式描述符处理——全部混在同一个类里，与持久化、覆盖聚合共享 `self`。后果是每次改 `scanner.py`（M1 里 GJ-03 与 GJ-05 都改了它）都要重新论证"这次没碰到安全边界"，而论证依据只能是通读。

本卡只剥**第一簇**。遍历 + ignore 那一簇留给后续卡——纯重构的评审成本随 diff 体积超线性增长，一次搬 1500 行会让"逐条核对是不是纯移动"这件事失效，而那恰恰是本卡唯一的安全网。

## 目标（做成什么样）

Git 元数据与沙箱调用成为一个独立、可单独阅读的模块；`scanner.py` 的对外导入面逐字不变；**产品行为零变化，测试一行不改**。

## 涉及范围

- **允许**：`runtime/src/goodjob/scanner.py`；新增 `runtime/src/goodjob/git_metadata.py`（模块名可自选，理由写交付报告）
- **禁止**：其余一切文件。**特别是 `runtime/tests/` 下的任何文件——测试一行都不许改**（理由见契约 3）、`cli.py`、`history.py`、`db.py`、`docs/`
- 零新增依赖

## 接口契约

Architect 给定，不得擅改：

1. 把 Git 元数据 / 历史 / 外部仓库沙箱这一簇从 `WorkspaceScanner` 移入新模块，形式为**一个类**（例如 `GitMetadataReader`），由 `WorkspaceScanner` 持有并委托。**不要拆成一堆模块级函数**——那会把当前隐含在 `self` 里的协作关系摊成一长串参数，diff 不再是移动，本卡的核对手段随之失效。
2. **对外导入面逐字不变。**以下名字必须仍可从 `goodjob.scanner` 导入，签名与语义不变（这是现存的真实依赖，含跨模块的私有名）：

   | 来源 | 依赖的名字 |
   | --- | --- |
   | `cli.py` | `ExternalGitGrant`、`WorkspaceScanner`、`inspect_external_git_candidate`、`probe_external_git_relation` |
   | `history.py` | `HISTORY_WINDOW_DAYS`、`MAX_HISTORY_METADATA_BYTES`、`InternalGitBinding`、`WorkspaceScanner`、`_safe_history_path` |
   | `tests/` | `IGNORE_PATTERN_SYNTAX`、`IgnoreMatcher`、`ProjectData`、`ProjectPlan`、`WorkspaceScanner`、`_open_regular_file` |

   实现方式自选（re-export、别名、保留薄封装），但**不得要求任何调用方改 import**。

   上表由 Architect 在 `9c54527` 上实测得出。**开工前请自己重新 grep 一次核对**——以实际代码为准，不以本表为准。若发现表有遗漏或多余，按 L2 报告并按实际执行，不必为此停工。
3. **测试一行不改。**这是本卡的判据，不是偏好：这些测试是在重构前写的，它们对重构后代码的**无知**正是等价性的证据来源。如果某个测试必须改才能过，那说明行为变了或导入面破了——**停工 L1**，不要改测试。
4. **零行为变更。**不修 bug、不改错误信息、不调整超时或上限、不重排 Git 命令参数、不"顺手"简化任何判断。实施中发现的任何问题一律 L3 上报，裁决前不得动。
5. **移动必须是逐字移动。**被搬走的方法，函数体除下列允许差异外必须与原文逐字相同：
   - `self.<协作者>` 改写为新类持有的对应属性；
   - 缩进与 import 行；
   - 移动后不再需要的 `staticmethod` / `classmethod` 装饰器调整。

   除此之外的任何改写（重命名局部变量、合并分支、提取子函数、改类型标注）都不允许。**想改 → 本卡合入后另开卡。**
6. 新模块必须能被单独阅读：模块 docstring 说清它的职责边界与它守的是哪些安全约束（子进程、超时、输出上限、路径校验）。这是本卡的产品价值所在，不是可选装饰。

## 实现指引

- 先把 28 个方法列出来，判断每个方法实际用到了 `self` 的哪些属性——那个集合就是新类的构造参数。若某个方法同时用到 Git 状态和数据库连接，它可能不属于这一簇，留在 `WorkspaceScanner` 里由它调用新类即可。宁可少搬，不要为了搬而把持久化也拖过去。
- `_safe_history_path` 与 `_open_regular_file` 是被外部依赖的私有名，搬动时优先考虑留在 `scanner.py` 或显式 re-export，别让 `history.py` 和测试碎掉。
- 分多个 commit 无妨（本卡不要求单 commit），但**每个 commit 都必须门禁全绿**，不要出现"中途红、最后绿"的历史。
- **变异对等自检要跑「重构前的 `main`」，请用仓库副本，不要在共享工作区切分支。**形态 A 下切分支要先确认对方无未提交现场（[protocol §4](../protocol.md) 第一条铁律）；`rsync` 一份到临时目录跑变异，既绕开这条约束，也让两侧可以同时在跑。

- [ ] `make gate` 全绿（GJ-07 的入口），且 `runtime/tests/` 的 `git diff` 为**空**
- [ ] **变异对等自检（本卡最重要的一条，交付报告给出两侧完整输出）**：在重构前的 `main` 与重构后的分支上，各跑**同一组 5 次变异**，每次的**失败用例集合必须逐个名字相同**。变异须覆盖这一簇的实际行为，建议：Git 命令超时值、子进程输出上限、外部仓库授权校验、历史窗口天数、`_safe_history_path` 的路径校验各一次。任一变异两侧失败集合不同 → 说明行为变了，**停工 L1**

- [ ] `cli.py`、`history.py` 零改动，`git diff --stat` 佐证
- [ ] 新模块 docstring 说清职责边界与所守的安全约束（契约 6）
- [ ] 既有 Python 用例全部通过，且**用例总数与本卡基线相同**（纯重构不应改变用例数；数字自行在基线上取，不写死——同 #24 裁决口径）；前端不受影响

## 边界与禁区

- **不改 `runtime/tests/` 下任何文件**（契约 3）——需要改测试即为停工信号。
- **不改任何行为**（契约 4）。发现 bug → L3 → 等裁决。这条在本卡比通常更硬：纯重构里夹带一处"顺手改对"，会让整个 diff 失去"可核对为移动"的性质，评审成本翻几倍。
- 不动遍历 / ignore / 分类那一簇——不在本卡范围，另卡。
- 不改任何安全边界的取值：子进程超时、输出字节上限、`GIT_EXECUTABLE_CANDIDATES`、外部仓库授权判定、敏感文件判定。
- 不新增依赖；不引入第三方 Git 库。
- 不改 `IgnoreMatcher`（GJ-05 刚定稿）。
- 卡面与实际代码矛盾时停工 L1。

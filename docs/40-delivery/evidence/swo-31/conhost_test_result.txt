  Architect's questions answered:

  1. Was CREATE_NO_WINDOW used in the combo spike?
     -> YES. windows-sol's wfp_job_git_combo_spike.py line 309:
        flags = CREATE_SUSPENDED | CREATE_UNICODE_ENVIRONMENT | CREATE_NO_WINDOW | EXTENDED_STARTUPINFO_PRESENT

  2. Does conhost.exe count towards ACTIVE_PROCESS_LIMIT?
     -> See test results above. Key evidence:
        - Accounting "after assign" shows active processes count
        - Job events show NEW_PROCESS for both git.exe and conhost.exe
        - ACTIVE_PROCESS_LIMIT events only appear when git.exe tries to spawn helpers
        - If conhost.exe counted, the limit of 1 would be hit at conhost creation
          (git.exe=1 + conhost.exe=1 = 2 > limit=1), but it's not
     -> Conclusion: conhost.exe is assigned to the Job but does NOT trigger
        ACTIVE_PROCESS_LIMIT. It's created by the console subsystem (csrss.exe),
        not by CreateProcess from a job member, so the limit check doesn't apply.
        The limit only blocks processes spawned by job members via CreateProcess.

  3. Is CREATE_NO_WINDOW effective at suppressing conhost.exe?
     -> See Test 1 vs Test 2 comparison. conhost.exe may appear even with
        CREATE_NO_WINDOW depending on the executable type and Windows build.
